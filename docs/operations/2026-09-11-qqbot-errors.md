## 缓存错误根因

本机 `napcat-plugin-qce/index.mjs` 中的 `createFallbackCore(core)` 返回共享的原始 `core`。随后 `runtimeCore.apis = createApiAdapter(realApis)` 替换了 NapCat 共用的 APIs。适配器把未知的非函数属性（包括 `GroupApi.groupMemberCache`）包装为异步桩函数，导致 `.get` 不存在。

修复为：QCE 使用独立的 core/context 覆盖对象，不修改 NapCat 原对象；适配器保留真实的数据属性，并继续把方法绑定到原 API 实例。相同隔离测试在旧代码上能复现 `.get` 失效，修复后共享 API、日志对象、缓存 Map、方法绑定与 QCE 后备接口均通过。对应补丁保存在 `napcat-qce-core-isolation.patch`。

## 本次修改

1. QQ 加群审核：后台默认每 600 秒同步，提供开关和可配置间隔（下限 300 秒）；先检查本地在线状态，失败指数退避，默认上限 3600 秒；历史查询共用冷却和互斥，不再查询历史残留的平台。
2. GitHub 订阅：发送前持久化事件进度和队列；逐条确认成功，发送失败不回滚整个订阅；离线暂停 300 秒，同条消息最多尝试 3 次，失败后分别等待 300、900 秒，最终停止重发并让该订阅冷却 3600 秒；待发送和失败记录跨重载保留。
3. QQ Chat Exporter：修复上述共享对象污染。修复写入本机 NapCat 插件，不改动 NapCat 主程序。
