# 2026-09-25 审核诊断与简称修正

## 变更依据

近期实际审核中，`24-SDUT` 被误解释为山东科技大学；同一人的两条 `23-hbut` 先被留给人工，再识别成湖北工业大学通过。新增参考映射为 SDUT=山东理工大学、SDUST=山东科技大学、HBUT=湖北工业大学。官网核对：[山东理工](https://www.sdut.edu.cn/)、[山东科技](https://www.sdust.edu.cn/)、[湖北工业](https://www.hbut.edu.cn/)。

四非排除名单仍采用 [2022 年第二轮双一流名单](https://www.gov.cn/zhengce/zhengceku/2022-02/14/content_5673496.htm)，名单与固定规则放在申请字段之前。本次只为学校群更新配置，不把示例规则强加给其他群，也不改变邀请策略。

## 实际模型回归

使用配置中的 ECNU Plus、enabled/low、JSON Schema，单并发、无自动网络重试，14 个样本各测 2 次。样本见 `tests/fixtures/school_alias_regression.json`，覆盖上述简称、HEBUT/SWUFE/SYSU/WUT、近期被排除学校、矛盾 JXNU、缺失信息和 HNUST。

28/28 返回有效 JSON；28/28 资格结果符合预期，要求明确识别的校名也全部正确。这是针对已知问题的回归，不代表随机生产申请准确率，也不保证模型永不误判。测试不触发 QQ 审批或发送群消息。

## 诊断与计价

阶段记录区分模型请求、账号队列、在线检查和平台操作；查询仍受群管理员权限限制。重载 v3 共享队列时保留等待中的其他插件任务；统计或阶段落库失败不改变审核动作。

仅输出保存通过 `store_response` 控制；原始 usage 只保存已知 token 字段白名单。没有缓存计数时保留未知，不使用框架自动填充的零。模型总输出已包含思考时不重复相加。

ECNU 额度单价及峰谷规则按 [官方文档](https://developer.ecnu.edu.cn/vitepress/llm/limit.html) 在 2026-09-25 核对，使用 CREDITS 单位。根据调用开始时配置模型名和北京时间计价，避免后端返回模型名变化导致漏算。输入总量已知、缓存拆分未知时显示上下限；平台账单仍为最终依据。
